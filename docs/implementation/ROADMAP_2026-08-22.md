# Roadmap — from I29 to a thing that can be reached

Written after I28. Every count below was measured against the repository on
2026-08-22, not remembered.

---

## 1. The finding that should lead

**There is no way to deploy this.**

| Artefact | Count |
|---|---|
| GitHub workflows | 1 (`ci.yml`) |
| Deploy workflows | 0 |
| `Dockerfile` | 0 |
| Infrastructure-as-code files | 0 |
| Named hosting target anywhere in the repository | 0 |

Twenty-eight increments have made the platform correct, honest under outage,
observable, accessible and Turkish. **None of that has been reachable by anyone
except a person running `npm run dev` on this machine.** The API has never
served a request to a browser it did not also host; the database has never held
a row that outlived a test.

This is not a criticism of the order things were done in — a deployment of
something incorrect is worse than no deployment. But it is now the largest
single gap, it is the one item nothing else can substitute for, and it is
**blocked on an Owner decision that has been open since the release criteria
were drafted**: *where does this run?*

Everything in §3 improves a system nobody can visit. That is fine for a while
longer. It is not fine indefinitely.

## 3. What I can do next without asking anyone

In order. Each is one increment, one commit, complete with tests and a closure
record — the same shape as I21–I28.

### I29 — Turkish, Admin (last of three)

Seven surfaces: `/admin` and its six children. Finishes what I27 started and
lets `i10-accessibility`'s `ENGLISH` pattern be deleted rather than shrunk. The
first chance to add the pairwise substring check I28 left open, because the full
label set will finally exist.

**Size:** comparable to I28.

### I30 — The uncaught error, on 22 routes

| File kind | Count in `apps/web/src/app` |
|---|---|
| `error.tsx` | **0** |
| `global-error.tsx` | **0** |
| `not-found.tsx` | **0** |

I23–I25 taught the pages to handle the failures they *anticipate*. Nothing
handles the ones they do not. A `TypeError` in any of the 22 routes today
produces Next.js's built-in error screen — **in English, with no Turkish, no
correlation ID, and no route back into the application** — which is the exact
thing I27 and I28 have spent two increments removing everywhere else.

`notFound()` is called in thirteen places and there is no `not-found.tsx`, so
every one of them renders a default English page too.

This is the cheapest large win available and it needs no decision from anyone.

### I31 — Loading Behaviour

Six Frozen documents name it: UX-0001 §12, UX-0002 §13, UX-0003 §15, UX-0004
§13, UX-0005 §14, UX-0006 §14, UX-0008 §13, UX-0009 §17. **There are zero
`loading.tsx` files.**

Form submission is already handled — `useActionState`'s `pending` disables the
fieldset and swaps the label. What is missing is navigation: a person who clicks
into an Offering sees nothing happen until the server answers.

Note that I26 deliberately kept Empty and Loading separate, on the Owner's
instruction, so this is Loading only.

### I32 — Error Behaviour, the four remaining documents

UX-0003 §16, UX-0004 §14, UX-0008 §14, UX-0009 §18. I23 built the mechanism and
applied it to the public path; I24 applied it to the authenticated one. These
four sections state behaviour the mechanism can now express but has not been
pointed at.

Smaller than it sounds, because the hard part is already built.

### I33 — Observability for the half that has none

`/metrics` and correlation IDs exist in the API. **The web application emits
neither.** §12.2 has never been read against it. So when a person says "the site
was slow", there is no number to look at — the API's own latency histogram
covers only the part that was probably fine.

### I34 — One end-to-end test

**No E2E framework is installed.** 880 tests prove that units and contracts hold;
nothing proves that a browser can register, sign in, create a Business, publish
an Offering and find it. Every one of those steps is individually tested and the
sequence never has been.

This is also the first thing that will tell us whether the application actually
*runs* outside a test harness — which makes it the natural companion to §4.1.

## 4. What I cannot do, and who owns it

These are yours. Each blocks something real, and the first blocks everything.

### 4.1 Where does this run? *(blocks release entirely)*

Nothing can be built until this is named — a Dockerfile for Fly is not a
Dockerfile for Railway, and neither is a Vercel project. Once named, the work is
mine: build artefact, deploy workflow, migration-on-deploy, secrets, health
check, a real domain.

### 4.2 Do Offerings have images? *(scope, not preference)*

**The schema has no image, photo or media column of any kind.** A commerce
listing platform where no listing has a picture is a decision, and it is
currently being made by silence. If images are in v1, that is a migration, an
upload path, storage, size limits, moderation of image content, and alt-text —
a large piece of work that has never appeared in any plan.

### 4.3 Who answers for KVKK? *(R4.1–R4.4)*

No privacy notice, no aydınlatma metni, no data-subject-request path, no
retention policy published to users. The platform stores email addresses and
behavioural events for Turkish users. R4 of the release criteria names four
items; none has an owner.

### 4.4 §9.1 — how far does multi-language go? *(blocks i18n)*

Interface only, or content too, or a locale-scoped catalogue? I29 finishes the
Turkish consolidation regardless; this decides what happens after it.

### 4.5 Accept the release criteria

`docs/releases/V1_RELEASE_CRITERIA_CANDIDATE.md` — 24 items across Observable,
Deployable, Survivable, Lawful. Still a candidate. Until it is accepted there is
no agreed definition of *done*, which is why "how long to open beta" has no
answer.

## 5. What is deliberately not on this roadmap

- **Messaging (UX-0007).** The document is **Draft, version 0.2**, and it
  explicitly records as a TODO whether and how a Business replies. Half a
  conversation is not a feature. It is not implementable until PRD-0004 says
  what the other half is.
- **Search autocomplete, Home recommendations, pagination, facets.** Named in
  the original 2026-07-25 plan; either cancelled by a Frozen document or never
  in the Frozen baseline. Recorded in `ROADMAP_RECONCILIATION_2026-08-21.md`.
- **A visual redesign beyond I26.** The token layer exists and is enforced. What
  it has not had is a person looking at the result on a real screen.
